零基础入门手册

从零理解 AI：五个概念、一条路径、一个 GitHub

这份手册写给不懂技术的人。不需要任何编程背景，读完你就能明白这些词到底在说什么，知道从哪里开始动手，也知道该避开哪些坑。

一、先把五个词讲明白

不用背定义，先记住一个小故事：

你想让 AI 帮你把一份乱七八糟的会议记录整理成待办清单。

你用中文写下要求——这就是 Prompt（提示词）。
真正读懂你这句话、并把待办清单写出来的那套程序，叫 LLM（大语言模型）。
如果它不是装在你自己电脑上，而是跑在别人的服务器上，你的软件得通过一条"管道"去请它干活，这条管道叫 API。
如果它不只是回答一次，而是能自己拆解步骤、去翻你的日历、查资料、改文件、反复尝试直到把事情做完——那它就是一个 Agent（智能体）。
以上这一切加起来，统称为 AI（人工智能）。

AIArtificial Intelligence · 人工智能最大的那个圈

它不是一个具体产品，而是一整个领域的统称：让机器表现出类似人类智能的所有技术。语音识别、人脸识别、推荐算法、自动驾驶、大语言模型，都装在"AI"这个筐里。

打个比方：AI 相当于"交通工具"——汽车、火车、飞机都属于它，但它本身不是某一辆车。

LLMLarge Language Model · 大语言模型发动机

AI 里目前最主流的一类引擎。它被喂了海量文字（书、网页、代码）训练出来，核心能力其实是——预测下一个词该是什么。听起来简单，但把这件事做到极致，它就学会了写作、翻译、总结、推理、写代码。

ChatGPT、Claude、Gemini、DeepSeek、混元，这些名字背后都是 LLM。
它不知道今天发生了什么（有知识截止时间），也会一本正经地胡说（幻觉）。这两点是初学者最需要先建立的心理预期。

Prompt提示词方向盘

你写给 AI 的那段话，就是 Prompt。它不是编程，就是用大白话把你的需求说清楚。它直接决定了输出质量的高低——同一个模型，问法不同，结果能差出十倍。

一个够用的 Prompt 公式：背景（我是谁、什么场景）+ 任务（要你做什么）+ 要求（格式、字数、语气）+ 示例（照这个来）。

APIApplication Programming Interface · 应用程序接口输油管

让程序（而不是人）去调用 AI 的那条通道。你在网页上打字提问，是"人在用"；而你写的脚本、用的软件要自动调用 AI，就得走 API。

它有两个现实含义：一是要花钱（按用量计费，单位叫 token）；二是要有钥匙（一串叫 API Key 的密钥，泄露了别人就能拿你的钱去用）。

Agent智能体会自己干活的员工

把 LLM 从"一问一答的聊天框"升级成"给它一个目标，它自己去完成"的形态。它会自己拆解任务 → 调用工具（搜索、读写文件、操作软件）→ 检查结果 → 不对就重来 → 直到做完。

组成公式：Agent = LLM（大脑）+ Prompt（目标）+ 工具与 API（手脚）+ 记忆 + 循环。

它们之间的关系，一句话记住

AI
整个领域，最大的圈
LLM
AI 里的引擎，负责理解和生成
Prompt
你控制引擎的方向盘
API
让程序也能用上引擎的管道
Agent
引擎 + 方向盘 + 管道 + 手脚，组成一个会自己开车的司机

关键理解：AI 是领域，LLM 是引擎，Prompt 是方向盘，API 是油管，Agent 是会自己开车的司机。它们不是并列的五样东西，而是层层叠起来的——下层是上层的原料。

二、实际中是怎么用的

层次你在做什么用到哪些概念
日常使用
（人人可用）		聊天问答、写邮件、润色文章、翻译、总结长文档、让它解释看不懂的条款、让它帮你写 Excel 公式只用 Prompt + LLM，打开网页就能用，不需要懂任何技术
进阶使用
（会用工具）		上传一份 PDF 或 Excel 让它分析；让它联网查最新资料；把重复的事情交给它定时去做；用它生成一个小网页Prompt + LLM + 工具能力，本质还是"网页上操作"
开发/自动化
（需要一点技术）		写脚本批量处理文件、做一个自己的小工具、接进公司系统、搭建自动跑流程的 Agent要接触 API（Key、计费）和代码，通常配合 GitHub 管理

必须知道的一个词：token

AI 的"计费单位"和"记忆容量单位"。它不按字数算，按 token 算——大致上一个汉字约 1～2 个 token，一个英文单词约 1 个。每轮对话它"能记住"的内容有上限，这叫上下文长度。这解释了两个常见现象：聊得特别长之后它开始忘事；以及同样的问题，描述越啰嗦越贵。

三、零基础可以从哪些场景入手

原则是：不要从学原理开始，要从"用得上"开始。找一件你每周都要重复做、又烦又耗时的事，那就是你的切入点。

切入点具体怎么做为什么适合零基础
1. 当私人老师看不懂的合同条款、体检报告术语、报错信息，直接问它"用初中生能听懂的话解释这段话"零门槛、立刻见效，同时练出提问能力
2. 写作与改写写完的通知、邮件、总结，让它改得更简洁或更正式；或先口述要点让它成文马上能用在工作和生活里
3. 读长文档把几十页的 PDF 传上去，要它"列出关键结论和需要我决策的事项"体会 AI 处理信息的效率，远超自己读
4. 表格与数据不知道怎么写公式、怎么去重、怎么做透视表，把需求说清楚让它给公式并解释解决办公里最实际的痛点
5. 做个小东西让它给你生成一个简单的网页、计算器、抽签工具，直接保存成文件就能用第一次接触到"代码"，但不用自己写
6. 自动化重复操作让 AI 定时帮你抓取信息、整理文件、汇总日报从这里开始，你自然就会想了解 API 和 Agent

四、学习的先后步骤

  1. 第一级：会提问（先成为"提问高手"） 只练一件事——把话说清楚。学会给背景、给要求、给格式、给示例，学会在它答偏之后追加纠正，而不是重新问一遍。这一级不需要任何技术。
  2. 第二级：定场景（把 AI 接进你的真实生活） 选 2～3 件你每周必做的事，反复用 AI 去做，把有效的问法记下来，形成自己的"提示词模板库"。这一步会让 AI 从"玩具"变成"工具"。
  3. 第三级：懂边界（知道它什么时候不可靠） 建立三个认知：它会幻觉（编造事实和引用）、它有知识截止（不知道最新消息）、它不擅长精确计算和长链条推理。学会对关键数字、法条、引用做交叉验证。
  4. 第四级：会用工具（从"聊天"走向"干活"） 开始用带文件上传、联网搜索、能操作电脑/软件的 AI 工具。理解什么是"给 AI 一个目标，它自己分步骤完成"——也就是 Agent 的雏形。
  5. 第五级：接 API（真正的分水岭） 了解 API Key、计费方式、调用限制；哪怕不写代码，也能用现成的自动化平台搭一个流程。到这里你就从"用户"变成了"构建者"。
  6. 第六级：进阶（想深入再加） 学一点 Python，学会调用 API，学会用 Git 和 GitHub 管理你的代码与提示词。这时候你才真正需要"系统学 AI"，而前面的用法经验会让这一步顺畅得多。

路径的核心逻辑

先用，再懂，最后才造。绝大多数人卡住，是因为一上来就去啃"神经网络""Transformer"这类原理，结果三个月过去还是不会用。反过来，先用熟了，原理会变得好懂很多。

五、GitHub 能帮你什么

先说结论：GitHub 是一个给"文件"用的云端保管箱 + 时间机器 + 协作平台。它免费，只需要注册一个账号。

对你日常用电脑的帮助

它能解决什么说人话
文件有后悔药每次改动都留档，能看"哪天改了哪一行、为什么改"，能退回到任意一天的状态。彻底告别 方案_v3_最终版_真的最终.docx
换电脑不丢东西东西存在云端，新电脑上一条命令就全部取回来
免费拿到别人的工具海量开源软件、AI 工具、脚本都在上面，而且能看到说明（README）和别人的使用经验。很多软件的官网下载，源头就是 GitHub
遇到问题能找到答案Issues 区就是"别人的提问 + 作者的回答"。你遇到的报错，99% 已经有人问过并解决了
判断一个软件值不值得用看它的最近更新时间、star 数量、issue 回复速度——就能知道它是在活跃维护，还是已经被废弃

对你学 AI 的帮助

  • AI 生态几乎都从这里开始。模型、教程、课程、示例代码、提示词合集、各种 AI 工具，第一发布地往往就是 GitHub。
  • 试用新 AI 工具的标准动作就是 GitHub。看到有人推荐一个 AI 工具，通常的路径是：从 GitHub 下载 → 按 README 装好 → 运行。不会 GitHub，你连门都进不去。
  • 它是你存放学习成果的地方。建一个仓库当个人知识库，把笔记、提示词模板、练习代码都放进去，随时能看到自己一年来的进步。
  • 它是和 AI 编程助手配合的接口。现在很多 AI 编程助手（Copilot、Claude Code 等）是直接读取你的 GitHub 仓库来工作的。你的项目结构越清楚、README 写得越好，AI 帮你干活就越准。
  • 参与开源是最好的实战。给一个 AI 项目改进文档、提一个 issue、交一个很小的修改，就是零基础最合适的第一次实战。
  • 你的贡献记录是公开、可验证的。将来找工作时，这比自我介绍有说服力得多。

把 GitHub 和前面那五个概念连起来

AI 概念GitHub 在其中的角色
LLM模型本身的代码、训练方法、微调方案、使用文档都托管在这里。你想弄清一个模型怎么用、有什么限制，第一站就是它的仓库
Prompt大量"提示词合集"仓库就是现成的模板库，可以直接抄。更重要的是：你可以把自己的提示词存进仓库做版本管理——哪句改了、为什么改、改完效果变好还是变差，全都有记录
API官方仓库里的 README 和 examples 目录，就是"怎么写代码调用这个 AI"的标准教程。Learn API，从读仓库开始最快
Agent各种智能体框架、插件、自动化工具本身就是 GitHub 上的开源项目，而且典型的使用方式就是"下载下来跑起来"。这是 GitHub 和 AI 结合最紧的地方

反过来也成立

AI 也能帮你用 GitHub。你不懂命令没关系——报错贴给 AI 让它解释，README 让它帮你写，复杂的 git 操作让它给你现成命令。以后你甚至可以让 AI 智能体直接帮你在仓库里干活。
这就是最好的闭环：GitHub 存放你的提示词、代码和学习笔记，AI 则读取这些东西来帮你干活。

六、避坑清单

这三件事千万不要做

  • 不要把密码、身份证、银行卡、公司内部资料传给 AI。对话内容可能被保存，也可能在平台侧被查看。要处理的敏感信息，先手动去掉关键字段
  • 不要让 AI 直接替你做不可逆的操作。转账、删文件、群发邮件、提交正式材料——它可以帮你起草和检查，但最后一步必须你自己确认
  • 不要把 API Key 发到任何公开的地方（包括贴进公开仓库、群聊、截图）。一旦泄露，别人会用你的钱。如果不小心传了，立刻去平台吊销

这四个误区很常见

  • 以为 AI 说的都是对的。它对数字、法条、论文引用、历史细节的错误率不低。凡是要用来做决定的，务必核对原始来源
  • 指望一句话问到完美答案。正确姿势是多轮对话：先让它给个初稿，再逐步修正。迭代才是常态
  • 一上来就学原理。先会用，再懂原理——顺序反了最容易半途而废
  • 问得太笼统。"帮我写个方案"和"我是物业公司行政，要给业主写一份电梯检修停用通知，200 字以内，语气正式但不生硬"，结果完全不同
